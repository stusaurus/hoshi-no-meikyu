# 星の迷宮 — STANDARD（Web試作品）

> **開発中 / 未公開のプロトタイプ**。カード枚数、盤面サイズ、星・壁の配置ルールは検証用の暫定設定です。

## コンセプト
足の生えたロケットが星を集める、秘密情報と駆け引きのボードゲーム。
星の得点や壁の正体は隠され、星を確保するとその場に自分の旗が立って移動の障害物に変化します。得点は最終ラウンドまで公開されません。

## このブランチで遊べるもの
- 2〜4人で1台の端末を交代して対戦、または人間1人＋初級CPU1〜3体で対戦
- 検証用7×7 / 8×8 / 9×9盤面
- 固定の初期手札、2アクション制、6ラウンド
- 裏向きの星（0〜3点）と裏向きの壁（通常・反発・一方通行・幻影）
- 壁を移動、星を引き寄せる、相手ロケットを動かす、探索、バリア、3種類の移動
- 第4ラウンド前の追加配置、旗による通行妨害、最後の得点公開
- 交代画面で前のプレイヤーの手札・秘密情報を通常画面から隠す

## CPU対戦（初級）

トップ画面の「遊び方」で「1人＋CPU 1〜3体」を選択してください。CPUが星や壁を配置し、手番で自動行動します。

- 星に近づく移動を優先し、流星ダッシュ・ジャンプ・探査・妨害などを状況によって使う
- CPUが知らない星の点数は期待値として扱い、未公開の壁の種類は先読みしない
- まだ**初心者向けの試作CPU**。CPUの強さ、勝率、最適な盤面は検証していない
- 友達同士の交代プレイも従来どおり使える

## iPhoneから試すプレビュー（GitHub Pages）

Webプレビューのファイルと自動デプロイ処理は準備済み。ただし現時点ではPagesの設定が有効になっておらず、URLからまだ遊べません。

1. [リポジトリのPages設定](https://github.com/stusaurus/hoshi-no-meikyu/settings/pages)を開く。
2. Build and deployment の **Source** を **GitHub Actions** にする。
3. [プレビューワークフロー](https://github.com/stusaurus/hoshi-no-meikyu/actions/workflows/preview-pages.yml)を再実行する。
4. デプロイ成功後にのみ公開URLの動作を確認する。

**注意：** `noindex` と `robots.txt` は検索エンジン向けであり、アクセス制限ではありません。公開URLを知る人はアクセス可能です。開発中は「きょうボド」への導線や販売ページは設置しません。

## CPU検証データ

[900試合ベースライン](docs/CPU-BASELINE-2026-10-14.md)を記録。2・3・4人 × 7・8・9マスの全9条件で各100試合の進行テストを完了しました。先手の偏りや星の確保率を調査中で、盤面サイズはまだ決めません。

## 開発者向け
追加のインストールなしで `index.html` をブラウザで開きます。ローカルサーバーを使う場合：

```bash
python3 -m http.server 8000
# http://localhost:8000/
```

Node.jsを利用した操作・ルールの基本スモークテスト：

```bash
node tests/smoke.mjs
node tests/smoke.cjs
node tests/interactions.cjs
node tests/cpu.cjs
```

## 制限と次の工程
- このGitHubブランチはローカルで交代して遊ぶための**基本実装**です。遠隔オンライン対戦・会員登録・購入機能はありません。
- 暗号的な秘密保護はありません。ブラウザの開発者ツールから情報を見られるため、遠隔対戦ではサーバー側の権限管理が必要です。
- 正式な「足のあるロケット」のイラストはまだ仮表示です。
- 初級CPU対戦と900試合のベースライン調査を実施済み。座席ローテーション・異なるCPU方策・人間の対戦によるバランス検証はこれから行います。
- 本番公開や「きょうボド」へのリンク追加は、実画面・操作・ルールの検証後に行います。
